## 1. High-Level System Architecture

In a monolithic app, your order controller directly calls your database and delivery service in a single HTTP request. If the delivery system goes down or runs slowly, the customer’s checkout hangs and fails.

In our **Event-Driven Architecture (EDA)**, each service is completely independent:

```text
               +-------------------------------------------------+
               |                   RABBITMQ                      |
               |                 (Message Bus)                   |
               +-------+-----------------+-----------------+-----+
                       ^                 |                 |
     Publish Event     |           Listen |          Listen |
  OrderSubmittedEvent  |                  v                 v
                 +-----+------+    +------+-----+    +------+-----+
                 |  Ordering  |    |  Delivery  |    | Restaurant |
                 |  Service   |    |  Service   |    |  Service   |
                 +-----+------+    +------+-----+    +------+-----+
                       |                  |                 |
                       v                  v                 v
                 [Orders DB]        [Delivery DB]     [Restaurant DB]
                 (PostgreSQL)       (PostgreSQL)       (PostgreSQL)

```

### Core Architectural Principles We Will Enforce:

* **Database-per-Service:** Each microservice owns its own PostgreSQL database. `OrderingService` cannot query `DeliveryService`'s database directly.
* **Asynchronous Integration Events:** When an order is placed, `OrderingService` publishes an `OrderSubmittedEvent` to RabbitMQ and returns a response immediately. It doesn't wait for the driver to be assigned.
* **CQRS (Command Query Responsibility Segregation):** Inside services, we separate write operations (Commands like `CreateOrderCommand`) from read operations (Queries like `GetOrderByIdQuery`) using **MediatR**.
* **Clean Architecture / DDD:** Each microservice is split into layers (`Domain`, `Application`, `Infrastructure`, `API`) to keep business rules independent from frameworks.

## 🚀 Phase 1, Step 1: Infrastructure Setup

Our very first step is to create the local development environment using **Docker Compose**. We need:

1. **RabbitMQ** (with Management UI on port `15672`)
2. **PostgreSQL** (to host databases for our microservices)

### Your Task: Create `docker-compose.yml`

Create a folder named `FoodDelivery` on your machine, open it in VS Code, and create a `docker-compose.yml` file with this exact content:

```yaml
version: '3.8'

services:
  rabbitmq:
    image: rabbitmq:3-management
    container_name: fooddelivery-rabbitmq
    ports:
      - "5672:5672"     # AMQP messaging port
      - "15672:15672"   # Management Dashboard UI
    environment:
      RABBITMQ_DEFAULT_USER: guest
      RABBITMQ_DEFAULT_PASS: guest

  postgres:
    image: postgres:16-alpine
    container_name: fooddelivery-postgres
    ports:
      - "5432:5432"
    environment:
      POSTGRES_PASSWORD: postgrespassword
    volumes:
      - postgres_data:/var/lib/postgresql/data

volumes:
  postgres_data:

```

### How to Run & Verify:

1. Open your terminal in the `FoodDelivery` folder.
2. Run: `docker compose up -d`
3. Open your browser to `http://localhost:15672` (Username: `guest`, Password: `guest`).

Once you have verified that the RabbitMQ management page loads, let me know, and we will initialize the .NET solution and our shared integration events library!
